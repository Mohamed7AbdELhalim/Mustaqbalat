## 1. تعريف المشروع والمشكلة التقنية التي يعالجها

**مستقبلات (Mustaqbalat)** هو مشروع برمجي مفتوح المصدر يعالج مشكلتين عمليتين في آنٍ واحد:
1. **الإجهاد البصري الناتج عن إضاءة الشاشات والخلفيات البيضاء:** يعمل البرنامج تلقائياً وبشكل افتراضي فور فتح أي صفحة ويب أو مستند `PDF` ليتيح خفض سطوع الشاشة أو تعزيزه، وإسقاط طبقات تعتيم شفافة (`Overlay Layers`) فوق المواقع، وتفعيل الوضع الداكن الذكي الذي يحافظ على ألوان الصور والفيديوهات، وتطبيق أي درجة لونية عبر كود `HEX` أو عجلة الألوان.
2. **ضيق المساحة التخزينية ومحدودية موارد الجهاز:** بُني المشروع بالكامل بصفر مكتبات خارجية (`0 npm dependencies`) وبلا حزم بناء ثقيلة، وزُوّد بمحوّل ويب يعمل داخل الذاكرة المؤقتة للمتصفح (`RAM`) يحوّل الأداة فوراً إلى إضافة سحب وإفلات لا تستهلك بايتاً واحداً من القرص الصلب (`0 Bytes Bookmarklet`)، أو سكربت تلقائي (`Userscript`)، أو حزمة متصفح مضغوطة فائقة الصغر، مع رصد حي ودقيق لحجم استهلاكها من الذاكرة والمعالج على مدى الأيام والأسابيع.

## 2. المواصفات الوظيفية الكاملة للبرنامج

| محور الوظيفة | التفاصيل التقنية المنفذة في الكود |
| :--- | :--- |
| **التشغيل التلقائي ونطاق العمل** | يعمل افتراضياً في مرحلة `document_start` قبل رسم الصفحة لمنع الوميض الأبيض عبر `<all_urls>` وجميع الإطارات الفرعية (`all_frames`)، مع مفتاح إيقاف شامل وزر استثناء خاص بكل موقع (`excludedSites`). |
| **التحكم بالسطوع (تقليل وزيادة)** | نطاق تحكم متصل من `20%` (تعتيم ليلي عميق) إلى `100%` (إضاءة طبيعية) وحتى `150%` (زيادة وتعزيز إضاءة الشاشات الباهتة)، مدعوم بـ 5 أزرار ضبط فوري. |
| **طبقات التعتيم وآليات الدمج** | طبقة تعتيم مستقلة (`0%–85%`) فوق كامل نافذة العرض (`pointer-events: none`) مع ثلاثة أوضاع تشغيل: دمج ذكي (`hybrid`)، طبقات فوق الموقع فقط (`overlay`)، أو فلتر رسومي فقط (`filter`)، بالإضافة لتخفيف وهج البياض وضبط تباين النص. |
| **الوضع الداكن للصفحات وملفات PDF** | 4 أنماط متخصصة: `smart` (يعكس الصفحات الفاتحة ويعيد عكس الصور والفيديوهات لحفظ ألوانها الطبيعية)، `warm-dark` (داكن دافئ للقراءة)، `amoled` (أسود عميق)، و`pdf-dark` (معاير خصيصاً لمستندات PDF). |
| **استوديو الألوان المتقدم (`HEX` & Wheel)** | عجلة ألوان رياضية مرسومة على `Canvas` مع تخزين مؤقت للبكسلات، إدخال مباشر لأكواد `#HEX`، قطّارة التقاط ألوان الشاشة (`EyeDropper API`)، أشرطة `RGB`، 6 أنماط دمج لوني (`mix-blend-mode`)، 8 لوحات لونية طبية جاهزة، وأشرطة مستقلة لدفء الألوان والتشبع وتدوير طيف الصفحة. |
| **دعم وقراءة ملفات `PDF`** | كشف تلقائي لروابط وعناصر `PDF` في المتصفح مع شريط تعتيم إضافي خاص ببياض صفحاتها، بالإضافة لقارئ ومعتّم `PDF` مدمج يقرأ الملفات المحلية بالسحب والإفلات داخل الذاكرة المؤقتة (`Blob URL` — `0 بايت` تخزين). |
| **مراقبة الموارد (حي + أيام وأسابيع)** | مؤشر استهلاك مباشر داخل الصفحة (`In-Page HUD`) يعرض الذاكرة بالكيلوبايت (`~18 KB`) وزمن المعالج (`~0.20 ms`) ومعدل الإطارات (`FPS`)، ولوحة إحصائيات كاملة بآفاق `7 أيام`، `14 يوماً`، `4 أسابيع`، و`8 أسابيع` مع تصدير `JSON`. |
| **محوّل إضافات الويب عديم المساحة** | يجمع الكود داخل ذاكرة المتصفح إلى 3 صيغ قابلة للتخصيص المسبق: `Bookmarklet` (`0 بايت` على القرص)، `Userscript` تلقائي (`~8.5 KB`)، أو أرشيف `.zip` ثنائي مبني بمُجمّع `PKZIP / CRC-32` خالص لمتصفحات Chromium وFirefox. |
| **تكامل بلاغات `GitHub Issues`** | تبويب مخصص يكتشف الصفحات المقيدة أمنياً من المتصفح، ويحفظ سجل المواقع غير المتوافقة محلياً، ويولّد تذاكر بلاغات معبأة تلقائياً بالرابط والإعدادات التشخيصية على مستودع `GitHub` (مباشرة أو عبر `REST API`). |

## 3. التقنيات والأدوات المستخدمة

بُني النظام بالاعتماد الحصري على المعايير القياسية دون أي تبعيات خارجية:
- **معمارية المتصفح:** `WebExtensions Manifest V3` (متوافق مع Chrome, Edge, Brave, Opera, وFirefox 109+).
- **اللغات والواجهات القياسية:** `HTML5`, `CSS3 Custom Properties & Blend Modes`, `Vanilla JavaScript (ES2020+)`, `Shadow DOM API`, `HTML5 2D Canvas API`, `EyeDropper API`, `Blob & URL Object APIs`, `TypedArrays (Uint8Array / DataView)`.
- **بيئة الخادم والفحص الآلي المحلي:** `Node.js` بوحداته القياسية المدمجة فقط (`http`, `fs`, `path`, `vm`) دون حزم `npm` خارجية.
- **النشر والتكامل المستمر:** `GitHub Actions` (`.github/workflows/pages.yml`) للفحص الآلي والنشر على `GitHub Pages`.

## 4. كيفية الاستخدام والتشغيل السريع

للتفاصيل التشغيلية الكاملة لكل زر وتبويب، راجع **[دليل الاستخدام الكامل (`docs/ar/USER_GUIDE.md`)](./docs/ar/USER_GUIDE.md)**. وفيما يلي ملخص طرق التشغيل المباشرة:

### الطريقة الأولى: بدون تنزيل أو استهلاك مساحة نهائياً (للأجهزة محدودة السعة)
1. افتح المنصة الحية (`index.html` عبر المعاينة أو `GitHub Pages`).
2. انتقل إلى قسم **«أداة تحويل مستقبلات إلى إضافة ويب بدون تنزيل أو استهلاك مساحة»**.
3. اضبط قيمك الافتراضية المفضلة، ثم اسحب زر **«مستقبلات — راحة بصرية»** إلى شريط إشارات المتصفح (`Bookmarks Bar`) لتشغيله على أي موقع بصفر بايت على القرص، أو ولّد سكربت `.user.js` التلقائي بنقرة واحدة.

### الطريقة الثانية: تثبيت إضافة المتصفح الكاملة (`extension/`)
1. افتح صفحة الإضافات في متصفحك (`chrome://extensions` أو `edge://extensions` أو `brave://extensions`).
2. فعّل **وضع المطوّر (Developer mode)**.
3. اضغط **تحميل إضافة غير محزومة (Load unpacked)** واختر المجلد `extension/` من هذا المستودع (أو فك ضغط الحزمة المولدة من محوّل المنصة).

### الطريقة الثالثة: التشغيل والفحص الآلي للمطورين محلياً
```bash
# تشغيل الفحص الآلي لسلامة Manifest V3 والقواعد النحوية وتجميع الـ Bookmarklet
npm test

# تشغيل خادم المعاينة المحلي الخالي من الاعتماديات على المنفذ 3000
npm start
```

## 5. كيف صُنع البرنامج وتوثيق الكود سطراً بسطر

- **المرجع الهندسي المكتوب:** يتوفر الشرح الهندسي الكامل لكيفية تصميم وبناء كل خوارزمية ووحدة برمجية في المشروع كتابةً فقط داخل **[`docs/ar/HOW_IT_WAS_BUILT.md`](./docs/ar/HOW_IT_WAS_BUILT.md)**.
- **التعليقات التقنية سطراً بسطر داخل الكود المصدري:** جرى توثيق جميع ملفات المشروع البرمجية والتنسيقية والهيكلية الستة عشر (`10,088` سطراً إجمالياً عبر ملفات `.js`, `.css`, `.html`, `.yml`) بتعليقات تقنية عربية تشرح وظيفة كل سطر برمجي، وعلاقته بالسطر الذي يسبقه، وارتباطه ببقية أجزاء النظام، مع **التحقق الآلي من عدم حذف أو بتر أي سطر كود أصلي (`0` عمليات حذف)**.
- **توثيق ملفات `JSON` القياسية:** نظراً لأن معيار `RFC 8259` يمنع التعليقات داخل ملفات `.json`، وُثّقت جميع أسطر ملفات الإعداد الأربعة (`extension/manifest.json`, `messages.json`, `manifest.webmanifest`, `package.json`) سطراً بسطر في **[`docs/ar/JSON_CONFIGS_LINE_BY_LINE.md`](./docs/ar/JSON_CONFIGS_LINE_BY_LINE.md)**.

## 6. خريطة هيكلة المشروع ودليل المطوّر للمساهمة والتعديل

يوضح المخطط المختصر التالي البنية التنظيمية للمستودع (ولمعرفة أين تعدّل أو تضيف أي ميزة بالتفصيل راجع **[خريطة الهيكلة ودليل المطوّر (`docs/ar/ARCHITECTURE.md`)](./docs/ar/ARCHITECTURE.md)** و**[دليل المساهمة (`CONTRIBUTING.md`)](./CONTRIBUTING.md)**):

```text
Mustaqbalat/
├── extension/                  # حزمة الإضافة الكاملة (Manifest V3)
│   ├── core/                   # المحرك البصري الأساسي (mustaqbalat-engine.js)
│   ├── background/             # عامل الخدمة الخلفي وسجل الأيام والأسابيع (service-worker.js)
│   ├── popup/                  # نافذة التحكم المنبثقة ذات التبويبات الأربعة (HTML / CSS / JS)
│   ├── pages/                  # لوحة الإحصائيات التفصيلية + قارئ ومعتّم PDF بالذاكرة
│   ├── _locales/ar/            # حزمة التعريب الرسمية
│   └── icons/                  # أيقونات الإضافة القياسية (16, 32, 48, 128)
├── converter/                  # محوّل إضافات الويب بالذاكرة (Bookmarklet / Userscript / PKZIP)
├── scripts/                    # أداة التحقق والفحص النحوي الآلي (validate-and-convert.js)
├── assets/sponsors/            # الشعارات القابلة للتخصيص (مجتمع مرتكز + منصة قبيلة)
├── docs/ar/ & docs/en/         # أدلة الاستخدام والبناء والهيكلة والتواصل (متطابقة 1:1)
├── index.html & studio.js      # المنصة التفاعلية الحية وجسر محاكاة الإضافة
└── server.js & package.json    # خادم المعاينة المحلي وأوامر التشغيل (0 اعتماديات خارجية)
```
